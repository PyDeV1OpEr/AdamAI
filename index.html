Adam AI is an interactive evolutionary simulation by Mohammed Unais. A population of 500 agents is generated at random, scored on how far it gets through a guarded maze, then bred — highest fitness first — with small random mutations. No route is programmed here. The route is discovered, generation by generation, in the browser.

02 — Learning cycle

A random population becomes a route

No agent is told the answer, and no agent is told that it failed. Selection is the only signal: whatever travels further is copied more often, so small random edits accumulate into a path through the maze.

  1. Stage 01

    Initialise

    500 genomes, each ten random moves drawn from nine directions. Every agent starts on the same tile.

  2. Stage 02

    Execute

    Genomes replay in one shared maze, each direction held for six frames. Walls, guards and checkpoints act on all of them equally.

  3. Stage 03

    Evaluate

    Each agent is scored by its distance to the next checkpoint plus the precomputed route that remains from there to the goal.

  4. Stage 04

    Select

    A roulette wheel over the fitness sum. A better genome gets a larger slice of the wheel — never a guaranteed one.

  5. Stage 05

    Mutate

    The champion is cloned unmutated. Every other child redraws genes at mutationRate, weighted around a recent death.

  6. Stage 06

    Evolve

    Every five generations each genome gains five moves, so the search extends only as fast as prefixes are solved.

What improvement actually looks like

The first generation is noise: ten random moves from the corner, almost always ending against a wall. What survives is only what happens to drift further. Fitness then rises in small, monotone steps as longer genomes keep the successful prefixes intact.

Why it is slow

The genome is open-loop. It cannot see the guard, the wall or the checkpoint ahead — it replays a sequence of moves and dies when the sequence runs out. Improvement therefore comes from length and timing rather than strategy, and every checkpoint pushes the goal further away again.

  • Roughly 50 generations to the first checkpoint at 500 individuals, as reported upstream.
  • Later checkpoints take substantially longer: each gate enlarges the search space.
  • One elite slot and no crossover mean the population looks converged long before it solves the maze.

03 — The algorithm

What actually happens, cycle by cycle

This is a genetic algorithm, not deep learning and not reinforcement learning. There is no gradient, no reward model and no neural network. Six steps, all visible in the source.

  1. 01

    Initialise

    Each individual holds a Brain: an array of numberOfSteps (10) unit vectors chosen at random from eight compass directions plus a “stay still” vector. Every agent starts from the same tile.

  2. 02

    Execute

    A genome is a move budget, not a policy. Each direction is held for six frames, moving the agent tileSize/15 pixels per frame. Walls are resolved on the x and y axes separately, so agents slide along walls instead of sticking.

  3. 03

    Evaluate

    Fitness is computed when every agent is dead or finished. Reaching the goal scores 1/16 + 10000/steps²; otherwise the score falls off with the distance to the next unreached checkpoint. Collecting a checkpoint multiplies the score by 1.2, and the total is squared. Dying to a guard scales the distance estimate by 0.9 — which, because fitness is 1/d², slightly raises the score. That inversion is inherited, and documented rather than silently “fixed”.

  4. 04

    Select

    Roulette-wheel selection: each individual gets a slice of the wheel proportional to its fitness, then parents are drawn at random. Fit agents are likely to breed; unfit ones usually are not — but are never guaranteed to fail.

  5. 05

    Reproduce & mutate

    The elite is cloned unmutated into slot 0, so the best genome is never lost. Every other child copies its parent’s genome and, per gene, redraws that direction with probability mutationRate. Genes just before a guard-related death mutate five times more often.

  6. 06

    Expand the budget

    Every increaseEvery generations, increaseMovesBy new random directions are appended to every genome. Longer sequences can reach further, so progress compounds across generations — what the original README calls incremental learning.

No crossover

Reproduction is asexual: one parent, cloned, then mutated. There is no two-parent recombination anywhere in the codebase, and this page does not claim otherwise.

No neural network

The genome is a literal list of directions. Nothing infers state, extracts features or approximates a policy. Describing this as a neural network would be wrong.

Elitism, one slot

Only the single best individual survives unmutated. There is no fitness sharing, no diversity preservation and no speciation — which is why the population can converge prematurely.

05 — Engineering

What building this involved

The genetic algorithm and the maze are inherited. The interface, the instrumentation that makes the run legible, and the pipeline that ships it are the work of this rebuild.

01

Simulation in the browser

500 agents evolve per generation on canvas 2D at a measured ~60 fps, with no server, no build step and no external requests at runtime.

02

Genetic operators

Roulette-wheel selection over the fitness sum, a single unmutated elite slot, per-gene mutation and a move budget that grows on a fixed schedule.

03

Read-only instrumentation

The dashboard hooks in after calculateFitness() and samples generation, best and mean fitness, budget and checkpoints without writing back into selection.

04

Hand-drawn charting

The fitness chart is about 120 lines of canvas 2D with a log10 axis — written because a charting library was not worth the payload for one line chart.

05

Interaction design

Pause, replay, human control and restart share one state machine with the keyboard shortcuts, so a button and a key can never disagree about the current mode.

06

Delivery that fails closed

A GitHub Actions job checks required files, asset references and base-path safety before publishing, so a broken tree cannot reach Pages.

I built Adam AI to make evolutionary computation observable. Most explanations stop at a diagram of selection and mutation; the interesting part is what a population does under real selection pressure — how quickly it converges, where it stalls, and why an open-loop genome can memorise a route without ever understanding the maze.

My work is the redevelopment: reading the inherited algorithm line by line, fixing the defects that broke the demo, instrumenting the population so every displayed number is measured rather than decorative, and wiring up a deployment that validates itself. Known limitations

  • Open-loop genome: it cannot react to state, so it memorises timing rather than navigating.
  • One hand-authored level; no generalisation to an unseen maze.
  • Premature convergence — one elite slot, no crossover and no diversity pressure collapse the population onto similar paths.
  • Guard deaths are rewarded rather than penalised: the distance estimate is scaled by 0.9 before inverting, so dying close to a checkpoint scores higher. Preserved for comparability with the original.
  • Fitness is 1/d² then squared, so early generations are numerically tiny and flat on a linear axis.
  • Expect roughly 50 generations to the first checkpoint; later checkpoints take substantially longer.
